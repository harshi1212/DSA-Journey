# Phase 10 - Mock Interviews

## What is This Phase?

You've learned concepts. Now practice under pressure with time limits and realistic conditions.

---

## How to Conduct Mock Interviews

### Setup (5 min)
- [ ] Find quiet space, no distractions
- [ ] Have pen and paper ready
- [ ] Have 45 minutes uninterrupted
- [ ] Close all tabs except problem

### Interview Flow

**Section 1: Clarification (3 min)**
- [ ] Read problem 2-3 times
- [ ] Write down: Input, Output, Constraints
- [ ] Ask clarifying questions
- [ ] Identify edge cases

**Section 2: Approach Discussion (4 min)**
- [ ] Think of brute force first
- [ ] Discuss time/space complexity
- [ ] Mention which pattern it matches
- [ ] Explain optimizations you'd do
- **Talk out loud!** (This is crucial)

**Section 3: Coding (25 min)**
- [ ] Code cleanly with comments
- [ ] Use meaningful variable names
- [ ] Test as you code
- [ ] Write test cases

**Section 4: Testing (5 min)**
- [ ] Walk through provided example
- [ ] Test edge cases (empty, single, boundary)
- [ ] Trace through code to find bugs

**Section 5: Optimization (8 min)**
- [ ] Discuss how to improve further
- [ ] Code improvements if time
- [ ] Explain the improvements

## Scoring Rubric

Rate yourself 1-5 on:

1. **Understanding (1-5)**
   - 5: Immediately understood problem
   - 1: Took multiple reads

2. **Approach (1-5)**
   - 5: Explained approach before coding, pattern recognized
   - 1: Jumped to coding, no clear plan

3. **Coding (1-5)**
   - 5: Clean code, no bugs, great variable names
   - 1: Multiple bugs, hard to follow

4. **Testing (1-5)**
   - 5: Tested edge cases, found and fixed bugs
   - 1: Only tested happy path

5. **Communication (1-5)**
   - 5: Explained thinking throughout
   - 1: Silent coding

**Total Score**: (1+2+3+4+5) / 5

## Red Flags in Interviews

❌ **Silent coding** - Always explain  
❌ **No edge case testing** - Always test  
❌ **Hardcoding** - Don't customize for one test  
❌ **Not reading problem** - Read 2-3 times  
❌ **Jumping to optimization** - Get it right first  
❌ **Ignoring constraints** - Constraints drive approach  
❌ **Bad variable names** - Use descriptive names  

---

## Green Flags in Interviews

✅ **Talking through approach**  
✅ **Clarifying ambiguities**  
✅ **Writing test cases**  
✅ **Clean code**  
✅ **Discussing time/space**  
✅ **Testing edge cases**  
✅ **Handling bugs gracefully**

## Interview Day Preparation

### 1 Week Before
- [ ] Solve 3-4 problems of each difficulty
- [ ] Do 1 full mock interview per day
- [ ] Review all patterns and their use cases
- [ ] Write down your strengths and weaknesses

### 1 Day Before
- [ ] Light review (don't overdo)
- [ ] Get good sleep
- [ ] Prepare: pen, paper, water
- [ ] Mentally rehearse your approach

### Day Of
- [ ] Eat good breakfast
- [ ] Do warm-up problem (easy)
- [ ] Deep breaths before interview
- [ ] Remember: They WANT you to succeed!

---

## After Each Interview

**Reflection (10 min)**:
1. What went well?
2. What could improve?
3. What pattern did it use?
4. Could I solve it faster?

**Review (15 min)**:
1. Read other people's solutions
2. Note clever approaches
3. Understand different ways to solve

**Practice (30 min)**:
1. Solve a similar problem
2. Implement improvements you learned
