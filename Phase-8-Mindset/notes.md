# Phase 8 - Problem-Solving Mindset

## Core Principles

### 1. **Read Carefully**
- Read problem 2-3 times
- Identify input, output, constraints
- Check edge cases

### 2. **Think Before Coding**
- Draw examples on paper
- Think of brute force first (to understand problem)
- Then optimize

### 3. **Know Your Patterns**
- Two pointers? → Sorted array/string
- Sliding window? → Contiguous subarray/substring
- Hash map? → Frequency/lookup
- DP? → Overlapping subproblems
- Backtracking? → All possibilities

### 4. **Write Comments**
- Explain your approach (interviewer wants your thinking)
- Explain key lines
- Show time/space complexity

### 5. **Test With Examples**
- Write code, test immediately
- Test edge cases (empty, single, large)
- Fix bugs before submitting

### 6. **Optimize Gradually**
- Brute force first (make sure it's correct)
- Then optimize (add hash map, use pattern, etc.)
- Don't over-optimize prematurely

### 7. **Learn From Solutions**
- After solving, read other solutions
- Ask: How is their approach different?
- Try to understand better solutions
- Implement improvements

### 8. **Practice Deliberately**
- Not just quantity, but quality
- Understand why solution works
- Can you solve it again in 1 week?

## Interview Strategy

### Before Interview
1. Practice 50+ problems
2. Review all patterns
3. Know your strengths/weaknesses
4. Get good sleep night before

### During Interview
1. **Clarify (2 min)**
   - Ask about constraints
   - Confirm input/output format

2. **Discuss Approach (2-3 min)**
   - Explain your thinking out loud
   - Mention time/space complexity

3. **Code (15 min)**
   - Write clean code
   - Use meaningful variable names
   - Add comments

4. **Test (3-5 min)**
   - Test with provided example
   - Test with edge cases
   - Walk through your code

5. **Optimize (2-3 min)**
   - Discuss possible improvements
   - Code if time allows

### What Interviewers Look For
✅ Can you understand the problem?  
✅ Do you communicate your thinking?  
✅ Can you solve it correctly?  
✅ Do you optimize?  
✅ Are you confident?  

### Red Flags
❌ Jump to coding without thinking  
❌ Quiet, no explanation  
❌ Hardcoding for one test case  
❌ Not testing edge cases  
❌ Giving up too quickly

## Debugging When Stuck

1. **Walk through code with example**
   - Trace through step-by-step
   - Where does it go wrong?

2. **Check edge cases**
   - Empty input?
   - Single element?
   - All same?
   - Large numbers?

3. **Simplify problem**
   - Solve smaller version first
   - Then extend

4. **Rethink approach**
   - Is there a pattern you missed?
   - Wrong data structure?
   - Off-by-one error?

5. **Google/LeetCode discuss**
   - Read hints, not full solution
   - Don't just copy code
   - Understand the insight

---

## Mistakes to Avoid

1. **Confusing similar patterns**
   - Sliding window ≠ Two pointers
   - DP ≠ Greedy
   - Study differences

2. **Edge case blindness**
   - Always check empty, single, boundary cases
   - Write test cases BEFORE coding

3. **Premature optimization**
   - Get it working first
   - Then optimize
   - Wrong fast answer < Right slow answer

4. **Not reading problem constraints**
   - Array size limits
   - Integer limits
   - Time/memory limits
   - These determine which approach works

5. **Copy-pasting without understanding**
   - Defeat purpose of practice
   - You'll be exposed in interview
   - Code to understand, not to solve

## The Mindset

> "It's not about being smart. It's about practicing the patterns until they become automatic."

Every expert was once a beginner. The difference is:
- **Beginners**: Solve problems then forget
- **Experts**: Solve problems, understand why, practice until automatic

Your job: Practice deliberately for 12-16 weeks. You will see patterns everywhere.
